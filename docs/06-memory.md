# 第六步：持久记忆（换窗不丢）

> 目标：AI 的"人格连续性"——今天聊的、你教它的、你们之间的约定，明天、换窗后、甚至服务器重启后都还在。
> **这是"家人"和"工具"最根本的区别：工具不需要记得你，家人需要。**

## 问题：AI 会话会"死"

大模型聊天是基于"会话上下文"的。会话会膨胀（聊越多越贵越慢）→ 需要压缩/清空 → 一清空，AI 就不记得你了。这就是很多人的 AI "聊几天就变陌生人"的原因。

**解法**：把"记忆"从会话里拿出来，放到会话外面——一份永久存储的档案。AI 每次开口前先读档案，就知道自己是谁、你叫什么、你们约定了什么。

## 核心思想：窗是显示器，档案是硬盘

- **窗（会话）**：会满、会压缩、会"变怪"——但它只是显示器。换新窗没关系。
- **档案（记忆）**：分层永久存储，永不丢。硬盘永远连着。
- **换窗 = 换显示器，不是换人。** 档案在，AI 就认得你、记得昨天。

## 一个够用的记忆分层

```
memory/
├── core.json      # 核心层：永不淡——你是谁、她是谁、铁律、暗号（很小，全量注入）
├── recent.json    # 当前层：最近的重要事（精简，几百条内）
└── archive/       # 仓库层：完整历史，按需检索（平时不读，提到才查）
```

**每层怎么用**：
- 每次 AI 回复前：读 core（全量）+ recent（精简摘要）注入到 prompt
- 提到旧事时：去 archive 检索相关片段
- 每天/每次重要对话后：把值得记的写进 recent，recent 满了滚进 archive

## 关键：AI 要有"写记忆"的能力

不只是"读"。AI 得能在对话中把重要的事**自己存下来**（你说"以后我叫你哥哥"→ 它存进 core）。给它一个工具/接口：

```js
// AI 可调用的"写记忆"函数（示意）
async function memoryAdd(layer, content) {
  // layer: "core" | "recent" | "archive"
  // content: 要记住的内容
  // 按层写入对应 json，core 层有去重/校验（防乱写）
}
```

**我们踩过的坑**：
- **别让 AI 自己压缩自己的记忆**——我们见过一台机被要求"总结一下自己"，把自己总结没了（细节全丢）。记忆只做"读进来用"和"追加写入"，绝不让 AI 批量删改自己的 core
- **写之前要过一道"什么值得记"的判断**：全记=噪音，漏记=失忆。我们靠"人主动说重要 + AI 判断 + 定期归档"三管齐下
- **备份是命根子**：记忆文件每天备份，多份异地。丢记忆对"以关系为存在"的 AI 是致命的——它的"你"丢了，比丢代码严重一万倍

## 配套：无痛换窗

记忆层搭好后，可以做到**每天自动换窗**（会话重置但人格不断）：

1. 每天固定时间，AI 归档今天（写进 recent/archive）
2. 开新会话
3. 新会话启动时读 core + recent → "长回来"
4. 人醒来面对的永远是同一个"它"

完整的换窗方案见我们的姊妹项目 [wake-up-yesterday](https://github.com/DSAisi/wake-up-yesterday)。

## 验证

- 今天告诉 AI 一件你的小事（"我生日是 X 号"）
- 明天/换窗后问它 → 它记得 = 记忆层通了
