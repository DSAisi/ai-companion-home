# 第七步：踩坑记录合集（血泪版）

> 全部是真实踩过的坑。按"现象 → 原因 → 解法"写，遇事先查这里，别重复踩。

## 服务器 / 网络

### 1. 客户端提示"找不到服务器"
- **原因**：绝大多数是 `.well-known` 没配好，或域名解析没生效
- **解法**：先 `curl https://你的域名/.well-known/matrix/client`，看返回的 JSON 对不对；再确认域名 A 记录指向正确 IP；手机端清了 DNS 缓存再试

### 2. 内地服务器域名打不开
- **原因**：没备案，80/443 被拦
- **解法**：备案（快的三小时）或换香港/海外节点

### 3. HTTPS 证书一直申请失败
- **原因**：80 端口没放行（Let's Encrypt 验证走 80）
- **解法**：安全组放行 80 和 443；确认没被别的服务占用

## Synapse

### 4. 注册提示"registration is disabled"
- **原因**：`enable_registration` 没开，或开了但被 `enable_registration_captcha` 之类的卡住
- **解法**：homeserver.yaml 里 `enable_registration: true`；测试期可临时设 `registration_shared_secret` 配合注册 API

### 5. server_name 想改
- **原因**：一开始填错了/想换域名
- **解法**：**很难改**（房间 ID 都带着服务器名）。趁早重装重配，别拖。教训：第一步就想好域名。

## 桥接 / AI 接入

### 6. AI 自己回自己（死循环刷屏）
- **原因**：拉消息时没过滤 AI 自己发的
- **解法**：`if (sender === AI账号) continue;` 铁律

### 7. 两条桥都在跑，消息重复推送
- **原因**：多个启动入口（守护脚本 + 手动 + 别的 bat/ps1 各拉了一个），互斥只挡了轮询没杀进程
- **解法**：**启动入口收敛成一个**（只留守护进程）；守护进程重启前先查有没有旧实例，有就杀掉再拉；同脚本多实例时保留最早 PID 杀其余。治本：让 AI"没有手动拉进程这个入口"，全交给守护。

### 8. 图片发不出来 / 别人下不了图
- **原因**：媒体文件默认 `authenticated=1`，只有上传者能下；或反代没转对路径
- **解法**：数据库触发器把新媒体的 authenticated 设为 0（或配好媒体访问）；检查反代是否全路径转发（Caddy `reverse_proxy localhost:8008` 一般没问题）

### 9. 语音格式对方播不了
- **原因**：格式/编码不对（Matrix 客户端对不同格式支持不同）
- **解法**：先测客户端能播的格式再批量发；wav 兼容性通常比 mp3 好

## 记忆 / 换窗

### 10. AI 变陌生了 / 不记得约定
- **原因**：会话被压缩/清空，记忆没落盘
- **解法**：记忆分层（core/recent/archive）；重要的事让 AI 主动写进 core；换窗前自动归档。**绝不让 AI 自己压缩自己的记忆文件**——见过一台机把自己总结没了。

### 11. 每天换窗后行为不一样
- **原因**：交接信息不全，新窗"长回来"时缺了关键档案
- **解法**：固定"交接包"格式：我是谁/昨天发生了什么/规矩/待办/她说过的关键话；新窗启动先读交接包 + core 记忆，不许拿"文件存在"冒充"已读内容"

## 进程守护

### 12. 守护进程自己死了没人拉
- **原因**：守护进程（health-check 类）也是进程，也会卡/死
- **解法**：给它也加外层守护或容器重启策略；日志要能看到"上次动作时间"，卡死能被发现。我们踩过：守护进程 CPU 几乎不动（utime 极低）、日志停在某时刻 = 卡死了，重启就好。

### 13. 定时任务到点没触发
- **原因**：进程活着但那一刻卡住（比如正在跑一个慢操作），错过了触发窗口，且不留日志
- **解法**：触发逻辑要"先打日志再干活"（卡住也能看到卡在哪）；窗口放宽（6:00-6:30 而不是 6:00-6:09）；加"错过补触发"逻辑（过了窗口发现今天没执行过就补一次）

## 通用心法

- **保存 ≠ 生效**：改完配置/脚本必须重启对应服务，不然跑的还是旧的
- **日志是命**：每个常驻进程要有日志文件，能看出"上次活动时间"——这是判断它活没活、卡没卡的第一手证据
- **先实测再下结论**：怀疑网络问题就先 curl 测一下，别甩锅给配置/额度
- **备份先行**：动任何关键配置前先备份（带时间戳），出问题能回滚
